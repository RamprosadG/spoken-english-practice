# Agent Guidelines & Project Architecture

## Project Overview
- **Application**: Spoken English Practice
- **Framework**: Next.js 16+ (App Router, Turbopack, React 19)
- **Language**: TypeScript (Strict mode)
- **ORM & Database**: Prisma 7 with `@prisma/adapter-pg` and PostgreSQL
- **Styling**: Tailwind CSS v4, `react-icons`, shared UI primitives in `src/components/ui`
- **Speech & IPA**: Browser `speechSynthesis` for playback; `phonemize` for dialect-aware IPA
- **Drag and drop**: `@dnd-kit/core`, `@dnd-kit/sortable`, and `@dnd-kit/utilities` reorder the conversation turns in the create/edit modal

The project is at the **foundation + Presentation library + Sentence library + Vocabulary library + Conversation library + Practice workspace + authentication + home overview stage**. The app shell, navigation, UI primitives, database wiring, the Presentation library, the read-only presentation practice page, the inline Sentence and Vocabulary practice libraries, the Conversation library with its two-speaker practice page and drag-and-drop turn editor, the Practice feature, the Home landing page with live library totals, and cookie-based auth (email/password, Google, complete profile, update profile, update password, hidden admin registration) are in place. Home is a landing page now: it shows counts and navigation, and must not gain practice forms or editing without a requirement. Home still lists four stat cards and four destination cards — the conversation entry was deliberately left out by request, so adding it needs a new instruction. No page route is protected; auth drives the header controls and the account API, and presentation, sentence, vocabulary, and conversation mutations are admin-only. Every library row also carries `isPublished`: admins see drafts and published rows, everyone else (public users and signed-out visitors) sees published rows only, and vocabulary stores a `partsOfSpeech` enum that defaults to `noun`.

## Technical Rules & Best Practices

### 1. Layout & Navigation
- **Single shell**: All pages render inside `AppLayoutShell`. Do not create per-page sidebars or headers.
- **Sidebar state**: `AppLayoutShell` owns the mobile drawer state and passes handlers to `Navbar` and `Sidebar`. Keep it that way unless a cross-tree consumer appears.
- **Header content**: `Navbar` owns the mobile hamburger and the auth area. Signed out it shows **Login** / **Register**; signed in it shows `UserMenu`. Do not add other header content without a requirement.
- **Routes**: Home is `/`; the other visible pages are `/presentation`, `/sentences`, `/vocabulary`, `/conversations`, and `/practice`. `/presentation/[id]` is the read-only practice page for one saved presentation and `/conversations/[id]` the two-speaker practice page for one saved conversation. `/admin-register` exists but must stay unlinked from the sidebar. Sidebar order and labels are **Home**, **Important Vocabularies** (`/vocabulary`), **Common sentences** (`/sentences`), **Regular conversation** (`/conversations`), **Daily Presentations** (`/presentation`), **Live practice** (`/practice`), and each page `<h1>` repeats its sidebar label — keep those two lists in step when a name changes; paths, component names, and API routes stay as they are. Sidebar active state compares `pathname === href`.
- **Dynamic-route shell**: `AppLayoutShell` wraps `Sidebar` in `<Suspense>` with a width-preserving fallback. `usePathname()` must suspend while a dynamic route is prerendered — do not remove that boundary or turn it into a high-level page fallback.
- **Page content**: Pages render a `components/features/<area>/<Area>Header` component. Keep the established page container (`flex flex-col gap-6 w-full`). Every header subtitle renders at all breakpoints — do not hide it again with `max-sm:hidden`. The header is `flex flex-col sm:flex-row`, so below `sm` the title, subtitle, and the full-width action row simply stack; nothing is absolutely positioned, so the subtitle cannot overlap a neighbour.
- **Layout offsets**: The fixed header height lives in `--app-nav-height`; do not hardcode `pt-16` in the shell.
- **Styling baseline**: Preserve the existing shell classes (`w-72` desktop sidebar with a matching `lg:pl-72` content and header offset, `w-64` mobile drawer, `p-6 md:p-8`, indigo active state, slate borders). The desktop rail is widened because the longest label, **Important Vocabularies**, measures 153 px and only fits the `w-72` content box; keep the four offset sites (`Sidebar`, `SidebarFallback`, `AppLayoutShell` main, `Navbar` header row) in sync when the width changes. Style changes must be broad and intentional, not incidental to a refactor.
- **Brand mark**: the sidebar logo is `public/spoken-english.jpg` rendered through `next/image` (32 px box, `object-cover`, `alt=""` — the adjacent `h1` already names the app). It renders in three places that must stay identical: the desktop rail, the mobile drawer, and the `SidebarFallback` in `AppLayoutShell`. The browser-tab icon comes from `metadata.icons` in `src/app/layout.tsx` and points at the same file; `src/app/favicon.ico` was removed because file-based icon metadata outranks `metadata.icons`, so adding one back silently overrides the tab icon.

### 2. Prisma & Database
- **Client location**: The Prisma client is generated into `src/generated/prisma`. Always import the singleton from `@/lib/prisma`.
- **Build command**: `npm run build` is `prisma generate && next build`. `src/generated/prisma` is gitignored, so any clean checkout or CI host (Vercel included) must generate the client before `next build`; a bare `next build` fails there with `Module not found: Can't resolve '@/generated/prisma/client'`. Keep the generate step in the build script rather than committing the generated output.
- **Adapter**: Instantiate `PrismaClient` only through `@prisma/adapter-pg` as already wired in `src/lib/prisma.ts`.
- **TLS**: `src/lib/aiven-ca.ts` holds the Aiven root CA as a bundled string and `src/lib/prisma.ts` strips `sslmode`/`sslrootcert` from `DATABASE_URL` before pooling. Never reintroduce a `sslrootcert=<path>` dependency in runtime code paths: serverless bundles only contain traced files, so `pg` fails with `ENOENT: no such file or directory, open 'certs/ca.pem'` inside the first query. Keep `certs/ca.pem` committed — the Prisma CLI still needs the path form — and keep the `*.pem` gitignore removal.
- **Publication and part-of-speech columns**: `presentation`, `sentence`, `vocabulary`, and `conversation` each store `isPublished Boolean @default(true)`, and `vocabulary` also stores `partsOfSpeech PartsOfSpeech @default(noun)` — the `PartsOfSpeech` enum is `noun verb adjective adverb pronoun preposition conjunction interjection`. The migration that added them (`20261104055301_add_publishing_and_parts_of_speech`) is purely additive: one `CREATE TYPE` and `ALTER TABLE ... ADD COLUMN ... NOT NULL DEFAULT`, so existing rows were backfilled as published nouns and nothing was rewritten. Keep changes to these tables additive — the user's library content is hand-entered and there is no seed to regenerate it; `prisma migrate reset`, `db push --force-reset`, dropping a column, or a shadow-DB rebuild is never acceptable. No index on `isPublished`: it is a two-value flag and the repo only declares indexes Prisma can express.
- **Indexes**: the four library tables list by `sequence` then `createdAt`, so each carries the composite `@@index([sequence, createdAt])` — the single-column `sequence` index is redundant once the composite exists and was dropped. `conversation_line` is not a library table: it carries `@@index([conversationId, sequence])` because it is only ever read as one conversation's ordered turns. `presentation.title`, `sentence.text`, `vocabulary.text`, and `conversation.title` are `@unique`, and `User.email` relies on its `@unique` key alone; the extra `@@index(email)` was dropped for the same reason. Uniqueness is exact-match: case and whitespace variants are separate rows, and the create/update services map a `P2002` to `409` through `uniqueViolationError`. Search runs `ILIKE '%term%'`, which no btree can serve; a `pg_trgm` GIN index would, but it cannot be declared in the Prisma schema, so it would have to be hand-written SQL and would report drift — add one only when a table grows to thousands of rows.
- **Primary & foreign keys**: Use `String @id @default(uuid())`. Do not use integer autoincrement IDs.
- **Schema changes**: After editing `prisma/schema.prisma`, run `npx prisma generate` and `npx prisma migrate dev --name <name>`. A running `next dev` caches the `PrismaClient` on `globalThis` (`src/lib/prisma.ts`), so a model generated after it started stays invisible there: every existing route keeps working while a new one 500s on `prisma.<model> is undefined`. Restart the dev server after `prisma generate` instead of chasing it as a code bug, and prove the data layer separately with a one-off `npx tsx` script.
- **Seed**: The auth, presentation, sentence, vocabulary, and conversation models exist but there is still no seed script. Add one only when seed data is genuinely required, and wire it back into `prisma.config.ts` and `package.json` at that point.
- **Migrations**: Commit `prisma/migrations` alongside schema changes. Do not edit generated SQL after it has been applied.

### 3. Next.js & React 19 Standards
- **Server Components by default**: Add `"use client"` only for state, event handlers, or browser APIs. The shell components are client islands; page components stay server components.
- **Layered backend**: When features arrive, route handlers (`src/app/api/...`) delegate to `src/server/services/` and repositories. Validate inputs with Zod schemas from `src/lib/validations/`.
- **Server-rendered pages**: Feature pages should be Server Components that call their service directly and stream through `<Suspense>`. The Presentation page is the reference pattern: a static page shell with a fallback, plus an inner async component that awaits `connection()` and calls the service. Keep search, filter, and page state in URL search params — not in client state — so only filter bars, pagination, and modals are client islands.
- **List vs. KPI queries**: Pair each ledger list endpoint with an unfiltered summary endpoint for stat cards. Push search and filters into the Prisma `where` and paginate with `count` + `skip`/`take`.
- **Authentication**: Pages remain public. Do not add route guards, redirects, or role checks to pages unless a requirement explicitly asks for them. Presentation, sentence, vocabulary, and conversation create/update/delete are the exception at the service layer, enforced with `requireAdminUser()`. Reading them is the other exception: a non-admin — signed-in public user or signed-out visitor — only ever sees rows with `isPublished = true`, enforced inside the list, detail, and neighbour reads of each service, not in the page. See the Authentication section below.
- **Publication gate**: `src/lib/publishing.ts` owns the rule. `publicationWhere({ status, canViewUnpublished })` returns `{ isPublished: true }` unless `canViewUnpublished` is true, then `{}` for all statuses or `{ isPublished: status === "published" }` for a chosen one. Keep it fail-closed — the flag is optional, so an unresolved or absent role means published-only — and keep both the library page and `GET /api/...` handler deriving it from `canViewUnpublishedContent()` instead of trusting a `status` query param.
- **Request data**: If a page reads `request.url`, route params, or search params, await `connection()` before the read so it does not serve a stale prerendered snapshot. Put the `await connection()` and the data read inside a `<Suspense>` boundary so the route can still prerender its shell. `/presentation/[id]` and `/conversations/[id]` are the exceptions: each sets `export const instant = false` so the page blocks until the record loads and an unknown id can return a real `404`. Any route handler or page that reads cookies must do the same; put `await connection()` before the `try` block so framework control-flow errors are not swallowed by `handleApiError`.

### 4. Presentation Feature
- **Data model**: `Presentation` stores `id` (UUID), a unique `title`, `text`, `sequence`, `isPublished`, `createdAt`, and `updatedAt`, mapped to the `presentation` table. Sequence is not unique; list order is `sequence` ascending, then `createdAt` ascending, served by the composite index without a sort.
- **Read path**: `src/app/presentation/page.tsx` wraps `PresentationContent` in `<Suspense>`. That async component awaits `connection()`, reads the `search`, `status`, and `page` search params, and calls `listPresentations()` directly. The service awaits `connection()` again, resolves `canViewUnpublishedContent()`, and delegates to `findPresentationPage()`, which spreads `publicationWhere(view)` into the `where` alongside a case-insensitive title `contains`, runs `count` plus `skip`/`take`, and returns `buildPaginationMeta` output. The default page size is `PRESENTATION_PAGE_SIZE` (20). Do not call `resolveSessionUser()` in this Server Component — refresh logic can write cookies.
- **Write path**: Route handlers in `src/app/api/presentations/` parse with `presentationInputSchema`, call the service, and return `{ success, message, data }`. The service methods call `requireAdminUser()`, which throws `401` when signed out and `403` for non-admins. A `title` already taken by another row returns `409` with "A presentation with this title already exists."; editing a row while keeping its own title still succeeds. `GET /api/presentations` stays public, uses `parsePagination(searchParams, PRESENTATION_PAGE_SIZE)`, and passes `parsePublicationStatus(searchParams.get("status"))` through — the service, not the param, decides whether a draft may appear. Writes carry `isPublished` from the modal's Status dropdown.
- **UI**: The header combines the title, subtitle, and admin-only **New presentation** action. `PresentationFilters` wraps the debounced `SearchInput`; `PresentationSection` keeps search and page state in the URL via `router.replace`, owns the edit modal and SweetAlert delete, and renders `Pagination` when rows exist. `PresentationTable` shows a 30-character text preview with a `...` suffix, uses `FiEdit` for edit, and gates edit/delete on `role === "admin"`; admins also get a `warning` **Draft** `Badge` beside the title of an unpublished row, and `PresentationFilters` renders the admin-only `All statuses` / `Published` / `Draft` `Dropdown` (`PUBLICATION_FILTER_OPTIONS`) so `status` rides the URL. `PresentationFormModal` puts a `PUBLICATION_FORM_OPTIONS` **Status** `Dropdown` (`id="presentation-status"`, default Published) directly above the full-width Sequence input. Successful mutations call `router.refresh()`.
- **Practice route**: `src/app/presentation/[id]/page.tsx` awaits `connection()` and the `params` promise, calls `getPresentationWithNavigation()` (one row read plus `findPresentationNeighbors()`, which walks the same `(sequence, createdAt)` order as the library table with a keyset `OR` on each side), and renders `notFound()` when the record is missing — which includes a draft read by anyone who is not an admin, and `findPresentationNeighbors(cursor, view)` applies the same `publicationWhere(view)` to both keyset walks, so a draft is never a Previous/Next target for a public reader. The page container order is **back link + nav row, header, workspace**: a `flex flex-col gap-3` column holds the `FiArrowLeft` **Back to presentations** link (`self-start`) first and then `PresentationPracticeNav`, which is a server-rendered `<nav>` with **Previous** left and **Next** right, both carrying the `secondary` `Button` class recipe; a neighbour is a `Link`, and the first and last rows of the library render a real `disabled` `<button>` instead — no client state in this row. The header below starts at the presentation title (no `mt-3`, it is the first child) and its subtitle. `PresentationPracticeWorkspace` takes `title` and `text`: the read-only container renders the title as its own bold line (`font-bold`, `text-base`) with `mt-4` before the `whitespace-pre-wrap` body, `CopyTextButton` in the top-right of the card header copies `title + "\n\n" + text`, and `useSpeechPractice(text, title)` prepends the title so Start pronounces it first. It must not read or write the practice `localStorage` entry and must not offer text editing.
- **Validation**: Title 1–200 characters, text 1–20,000 characters, sequence an integer from 1 to 100,000, and `isPublished` from `isPublishedInputSchema` — a `boolean` with `.default(true)`, so a payload that omits it publishes rather than drafts. New rows default to `max(sequence) + 1` from `findNextPresentationSequence()`.

### 5. Sentence Feature (Inline Practice)
- **Data model**: `Sentence` stores `id` (UUID), a unique `text` (English sentence), `meaning` (Bengali meaning), `sequence`, `isPublished`, `createdAt`, and `updatedAt`, mapped to the `sentence` table whose list index is the composite `(sequence, createdAt)`. Sequence is not unique; list order is `sequence` ascending, then `createdAt` ascending.
- **Read path**: `src/app/sentences/page.tsx` mirrors the Presentation composition: `<Suspense>` → `SentenceContent` awaits `connection()`, reads the `search`, `status`, and `page` search params, and calls `listSentences()` directly. The service awaits `connection()`, resolves `canViewUnpublishedContent()`, and delegates to `findSentencePage()`, which spreads `publicationWhere(view)` in alongside a case-insensitive `contains` over **both** `text` and `meaning` inside an `OR`, runs `count` plus `skip`/`take`, and returns `buildPaginationMeta` output. The default page size is `SENTENCE_PAGE_SIZE` (20). Do not call `resolveSessionUser()` in this Server Component.
- **Write path**: Route handlers in `src/app/api/sentences/` parse with `sentenceInputSchema` and return `{ success, message, data }`. `createSentence`/`updateSentence`/`deleteSentence` call `requireAdminUser()` (`401` signed out, `403` non-admin), throw `ApiError(404, "Sentence is not found.")` for missing records, and return `409` with "A sentence with this text already exists." when the text belongs to another row. `GET /api/sentences` stays public with `parsePagination(searchParams, SENTENCE_PAGE_SIZE)` and forwards `parsePublicationStatus(searchParams.get("status"))`.
- **Validation**: `sentenceInputSchema` trims and requires 1–1000 characters for both `text` and `meaning`; `sequence` is a coerced integer from 1 to 100,000; `isPublished` is `isPublishedInputSchema`, so an omitted flag means published. New rows default to `max(sequence) + 1` from `findNextSentenceSequence()`.
- **Inline practice, not a route**: Sentences have **no** `/sentences/[id]` page. `SentenceSection` owns one `expandedId` state, so opening a row collapses the previous one automatically. `SentenceTable` renders a **Practice** / **Hide** toggle per row with `aria-expanded` and `aria-controls`, and passes `expandedRowId` plus `renderExpandedRow` to `DataTable`, which renders the panel in a full-width `colSpan` row. Do not convert this to a dedicated route or allow multiple open rows.
- **Practice panel**: `SentencePracticePanel` is listen-only and self-explanatory: the English sentence with its `InlineIpa` immediately beneath it, a per-sentence **Listen** button, the Bengali meaning under a `lang="bn"` `(বাংলা)` label, and `ListenControls` (accent, voice, speed) driven by `useListenSpeech()`. There is no pause, reset, IPA toggle, or IPA view dropdown — the learner picks an accent, optionally a voice from that accent's list, then listens. It must not read or write the Practice page's `localStorage` entry. Switching rows unmounts the panel, which cancels active speech.
- **UI**: `SentenceHeader` combines the title, subtitle, and the admin-only **New sentence** action. `SentenceFilters` wraps the debounced `SearchInput` (placeholder covers sentences and meanings); `SentenceSection` keeps search and page in URL params via `router.replace`, owns the create/edit modal and SweetAlert delete, and calls `router.refresh()` after mutations. `SentenceTable` shows the English text with the Bengali meaning beneath it (`line-clamp-2`), the practice toggle, and admin-only actions, plus a `warning` **Draft** badge next to an unpublished sentence for admins; `SentenceFilters` adds the admin-only status `Dropdown` and `SentenceFormModal` puts the **Status** `Dropdown` (`id="sentence-status"`) above the full-width Sequence input; sequence is stored and ordered on but never displayed.
- **Expandable rows and dropdowns**: `DataTable` accepts optional `expandedRowId` / `renderExpandedRow`; keep the expansion row at `colSpan={columns.length}` with `p-0`. `Dropdown` renders its menu through `createPortal` to `document.body` with `position: fixed`, `z-[70]`, viewport clamping, open-above flipping, capture-phase scroll/resize repositioning, and Escape close, so accent/voice/speed menus are not clipped inside the expanded panel. Do not revert the portal rendering to an absolutely positioned in-flow menu.

### 6. Vocabulary Feature (Inline Practice)
- **Data model**: `Vocabulary` stores `id` (UUID), the required and unique `text` (word), `meaning` (Bengali), `sentence` plus `sentenceMeaning`, optional `synonymText`/`synonymMeaning`/`synonymSentence`/`synonymSentenceMeaning`, optional `antonymText`/`antonymMeaning`/`antonymSentence`/`antonymSentenceMeaning`, `sequence`, `isPublished`, `partsOfSpeech` (the `PartsOfSpeech` enum, `noun` by default), `createdAt`, and `updatedAt`, mapped to the `vocabulary` table whose list index is the composite `(sequence, createdAt)`. Every synonym/antonym field is nullable; a group only renders when its word exists. Sequence is not unique; list order is `sequence` ascending, then `createdAt` ascending.
- **Read path**: `src/app/vocabulary/page.tsx` mirrors the Sentence composition: `<Suspense>` → `VocabularyContent` awaits `connection()`, reads the `search`, `letter`, `status`, and `page` search params (the letter is normalized to a single uppercase A–Z, otherwise ignored), and calls `listVocabulary()` directly. The service awaits `connection()`, resolves `canViewUnpublishedContent()`, and delegates to `findVocabularyPage()`, which spreads `publicationWhere(view)` into the same `where`. Search applies **only** to `text`, `synonymText`, and `antonymText` inside an `OR` with case-insensitive `contains` — never to Bengali meanings or sentences. The letter filter is a case-insensitive `startsWith` on `text`. Both are pushed into the Prisma `where` with `count` plus `skip`/`take`, returning `buildPaginationMeta` output. The default page size is `VOCABULARY_PAGE_SIZE` (20). Do not call `resolveSessionUser()` in this Server Component.
- **Write path**: Route handlers in `src/app/api/vocabulary/` parse with `vocabularyInputSchema` and return `{ success, message, data }`. `createVocabulary`/`updateVocabulary`/`deleteVocabulary` call `requireAdminUser()` (`401` signed out, `403` non-admin) and throw `ApiError(404, "Vocabulary is not found.")` for missing records. A `text` already owned by another row returns `409` with "This vocabulary word is already saved."; re-saving a row under its own word still succeeds. `GET /api/vocabulary` stays public with `parsePagination(searchParams, VOCABULARY_PAGE_SIZE)` and forwards `parsePublicationStatus(searchParams.get("status"))`.
- **Validation**: Word 1–100, Bengali meaning 1–500, example sentence and its Bengali meaning 1–1000. Optional fields accept missing/`null` (`.nullish()`) and are stored as `null` when blank — the form sends `null`, so keeping `.optional()` alone would reject valid submissions. `superRefine` rejects a synonym/antonym detail without its word. `sequence` is a coerced integer from 1 to 100,000; `isPublished` is `isPublishedInputSchema` and `partsOfSpeech` is `z.enum(PARTS_OF_SPEECH).default("noun")`, so a payload that omits either publishes the word and calls it a noun; new rows default to `max(sequence) + 1` from `findNextVocabularySequence()`.
- **Inline practice, not a route**: Vocabulary has **no** `/vocabulary/[id]` page. `VocabularySection` owns one `expandedId`, so opening a row collapses the previous one. `VocabularyTable` renders the word with a `neutral` **part of speech** `Badge` and — for admins, on an unpublished row — a `warning` **Draft** `Badge` beside it, then the Bengali meaning (`lang="bn"`) and a mobile-only IPA beneath it, an IPA column (hidden below `sm`, default `en-GB`), a **Practice** / **Hide** toggle with `aria-expanded`/`aria-controls`, and admin-only actions; sequence is stored and ordered on but never displayed. It passes `expandedRowId` plus `renderExpandedRow` to `DataTable` for the full-width `colSpan` panel. Do not convert this to a dedicated route or allow multiple open rows.
- **Practice panel**: `VocabularyPracticePanel` is listen-only and shows IPA automatically, with no pause, reset, IPA toggle, or IPA view dropdown. Above the card grid is a single row driven by `useListenSpeech()`: the word (slightly larger, left-aligned) and `ListenControls` (accent, voice, speed, right-aligned) on wide screens; `ListenControls` is `grid grid-cols-1 gap-3 sm:grid-cols-2 lg:grid-cols-3`, so the three dropdowns sit in one row from `lg`, two-up at `sm`, and stack one per row below `sm` under the word. Keep that responsive split. ### 7. Conversation Feature (Two-Speaker Practice)
- **Data model**: `Conversation` stores `id` (UUID), a unique `title` (what the conversation is about), `speaker1` and `speaker2` (display names only), `description`, `sequence`, `isPublished`, `createdAt`, and `updatedAt`, mapped to the `conversation` table with the same composite `(sequence, createdAt)` list index as the other libraries. `ConversationLine` stores `id`, `conversationId` (`onDelete: Cascade`), `text`, `sequence`, and timestamps, mapped to `conversation_line` with `@@index([conversationId, sequence])`. There is **no speaker column**: the speaker comes from parity — `sequence % 2 === 1` is speaker 1, otherwise speaker 2 — so the two voices always alternate and a stored row cannot drift into a monologue. Add a real `speaker` field only if a requirement needs non-alternating turns. Sequence is not unique; list order is `sequence` ascending, then `createdAt` ascending.
- **Read path**: `src/app/conversations/page.tsx` mirrors the Presentation composition: `<Suspense>` → `ConversationContent` awaits `connection()`, reads the `search`, `status`, and `page` search params, and calls `listConversations()` directly. The service awaits `connection()`, resolves `canViewUnpublishedContent()`, and delegates to `findConversationPage()`, which spreads `publicationWhere(view)` into the same `where` and applies a case-insensitive `contains` inside an `OR` over `title`, `description`, `speaker1`, and `speaker2`, then `count` plus `skip`/`take`, returning `buildPaginationMeta` output with `nextSequence` alongside. The list query never includes lines — the table needs only title, description, and the two names. `getConversationDetail()` and `getConversationWithNavigation()` include `lines` ordered by `(sequence, createdAt)` and throw `ApiError(404, "Conversation is not found.")`. The default page size is `CONVERSATION_PAGE_SIZE` (20). Do not call `resolveSessionUser()` in this Server Component.
- **Write path**: Route handlers in `src/app/api/conversations/` parse with `conversationInputSchema` and return `{ success, message, data }`. The payload carries `lines: string[]` where the **array order is the turn order**, so no line ids travel to the server. `createConversation`/`updateConversation`/`deleteConversation` call `requireAdminUser()` (`401` signed out, `403` non-admin). Both writes run in one `prisma.$transaction` (the parent row plus its turns) and finish with `findUniqueOrThrow` + `include`; update replaces the whole list with `lines: { deleteMany: {}, create: … }` because the incoming array is the whole truth — diffing by id would only add a failure mode. A `title` already taken by another row returns `409` with "A conversation with this title already exists."; editing a row under its own title still succeeds. `GET /api/conversations` and `GET /api/conversations/[id]` stay public with `parsePagination(searchParams, CONVERSATION_PAGE_SIZE)`; the list also forwards `parsePublicationStatus(searchParams.get("status"))`, and a draft id reads as `404` for anyone who is not an admin. Both writes carry `isPublished` from the modal.
- **Validation**: Title 1–200, each speaker name trimmed 1–60, description 1–500, `sequence` a coerced integer from 1 to 100,000, and `lines` 2–`CONVERSATION_MAX_LINES` (60) entries of 1–`CONVERSATION_LINE_MAX_LENGTH` (1000) characters with "A conversation needs at least two lines." `isPublished` is `isPublishedInputSchema`, so a payload without the flag publishes. New rows default to `max(sequence) + 1` from `findNextConversationSequence()`.
- **Library UI**: `ConversationHeader` states **Regular conversation** (the sidebar label) and `ConversationActions` renders the admin-only **New conversation** button seeded with `nextSequence`. `ConversationFilters` wraps the debounced `SearchInput` (placeholder covers title, description, and speaker name). `ConversationTable` columns are **Conversation** (title plus a 60-character description preview with a `...` suffix), **Speakers** (two `Badge`s, one per name), **Practice** (`TableActionLink` to `/conversations/[id]`), and admin-only **Actions**, where a `warning` **Draft** `Badge` sits beside an unpublished title; `ConversationFilters` adds the admin-only status `Dropdown`, and `ConversationFormModal` puts its **Status** `Dropdown` (`id="conversation-status"`) between the turn list and the full-width Sequence input. Sequence is stored and ordered on but never displayed. `ConversationSection` keeps `search`, `status`, and `page` in the URL via `router.replace`, owns the SweetAlert delete ("…and all of its turns will be permanently removed."), calls `router.refresh()` after mutations, and — because the list rows carry no turns — awaits `GET /api/conversations/[id]` before opening the edit modal.
- **Drag-and-drop turn editor**: `ConversationFormModal` renders `ConversationLineSorter`, built on `@dnd-kit/core`, `@dnd-kit/sortable`, and `@dnd-kit/utilities` (runtime dependencies, not devDependencies). `DndContext` + `SortableContext` with `verticalListSortingStrategy`; `PointerSensor` uses `activationConstraint: { distance: 6 }` so a click inside a turn textarea never starts a drag, and `KeyboardSensor` with `sortableKeyboardCoordinates` keeps space-then-arrows reordering available. The overlay renders the pure `TurnDragPreview` — never call `useSortable` inside `DragOverlay`. Each row is a drag handle button (`RiDraggable`, `title="Drag to reorder"`, `aria-label="Reorder turn N, <name>"`, `cursor-grab touch-none`), the speaker badge and label derived from the array index, a `rows={2}` textarea, and a remove action that is disabled at `MIN_LINES` (2) so the client cannot submit what the schema rejects. Turn keys come from a module counter (`line-N`) and are React/dnd-only; they never reach the API.
- **Practice route**: `src/app/conversations/[id]/page.tsx` sets `export const instant = false`, awaits `connection()` and the `params` promise, calls `getConversationWithNavigation()` (one row read plus `findConversationNeighbors()`, the same keyset `OR` walk the library uses, which applies `publicationWhere(view)` on both sides), and renders `notFound()` when the record is missing or is a draft the reader may not see. Container order matches Presentation: **back link + nav row, header, workspace** — `FiArrowLeft` **Back to conversations**, then the server-rendered `ConversationPracticeNav` (`secondary` **Previous**/**Next**, a `Link` for a neighbour and a real `disabled` `<button>` at the first and last rows), then the title header with `conversation.description` as its subtitle. `ConversationPracticeWorkspace` puts `CopyTextButton` in the top-right of the "Conversation text" card header, copying `title + "\n\n" + "Speaker name: turn"` per line, then renders the bold title and one tinted row per turn (`SPEAKER_ROW_CLASSES` + a name `Badge` + "Turn N") inside a `max-h-96` scroll region. It must not read or write the Practice `localStorage` entry and offers no text editing.
- **Speaker styling**: `src/features/conversation/speakerStyles.ts` maps `ConversationSpeaker` to a `Badge` variant (`info` / `success`) and to the row tint. Both maps are keyed by the speaker union, so parity remains the only source of the split — the two colours are the identity of each voice everywhere the turn list renders.
- **Two-voice playback**: `useConversationPractice({ speaker1, speaker2, lines })` is a separate engine from `useSpeechPractice` — do not merge them. It builds one `SpeechSynthesisUtterance` per turn and chains the next from the previous `onend`, so the two speakers keep different `utterance.voice`s inside one conversation. **One `accent` state serves both speakers** — the learner picks a single Accent, then a Voice per speaker; do not reintroduce a per-speaker accent. `PREFERRED_GENDER` (speaker 1 female, speaker 2 male) is what keeps the two automatic picks apart once both sides share an accent; if the machine only has one voice for that accent both speakers sound the same, which is why the per-speaker Voice dropdown exists. Choices live in React state, never `localStorage`, because voice selection is session-only by decision. The Web Speech API exposes no gender metadata, so `guessVoiceGender()` is a name-token heuristic used only to default and to label the voice list (`${voice.name} · ${gender}`); it and `buildVoiceOptions(voices, accent)` are imported from `@/features/practice/speechVoices`, the same module the single-voice pages use, so the token lists exist once. `buildVoiceOptions(voices, accent)` filters the list to the selected accent and is shared by both dropdowns; `resolveVoice()` prefers the picked `voiceURI`, then a matching-accent voice with the preferred gender, then any voice of that accent, then leaves the voice unset and shows the fallback notice. Changing the accent clears both hand-picked voices, because a voice belonged to the accent it was listed under. **The speaker names are never spoken**: only `turn.text` reaches the utterance — a name appears in the DOM, the control legends, and the clipboard, never in audio.
- **Playback state**: the action row is **Reset** (`secondary`, disabled while `idle`) → one **Start/Pause** flip button → the icon-only **Repeat** toggle (`RiLoopRightLine`, `aria-pressed`, white off / `secondary` on, same `border-slate-400` override rule as Practice). Pause at a turn boundary is honoured: `statusRef` marks the pause and `nextTurnRef` remembers the turn the chain stopped on, so the next Start resumes there instead of rewinding. Per-turn **Listen** in `ConversationIpaCard` speaks with `chained = false`, so Repeat loops the whole conversation only and never replays a single card, and Reset nulls `activeUtteranceRef` so the loop cannot fire afterwards. Every value read mid-playback (`turns`, `accent`, `pickedVoices`, `voices`, `speed`, `repeat`, `status`, `nextTurn`) is held in a ref, because a running utterance keeps the callbacks of the render that started it. Changing the accent, a voice, or the speed stops playback and announces why. Handlers are plain `const`s with no `useCallback` — the recursive `speakTurn` otherwise trips `react-hooks/immutability`.
- **Control layout**: `ConversationPracticeControls` stacks three blocks — a `grid grid-cols-1 gap-4 sm:grid-cols-2 xl:grid-cols-3` row of **Accent** (labelled "Accent (both speakers)"), **Speed**, and the **Show IPA** switch; then a `grid grid-cols-1 gap-4 sm:grid-cols-2` row of the two **Voice** dropdowns, labelled `Voice (<name>)` — e.g. `Voice (Mina)`, `Voice (Raju)` — resolved from the turns with a `Speaker 1` / `Speaker 2` fallback and fed by the shared accent-filtered `voiceOptions`; then the unchanged `mt-5 border-t border-slate-100 pt-5` action row. Those dropdowns carry no speaker `Badge` pill above them — the name inside the label is the only marker in that row, while `SPEAKER_BADGE_VARIANTS` still identifies each voice in the turn list, the IPA cards, the drag-and-drop editor and the library table. Keep the fieldsets of the old per-speaker layout out — the accent belongs to the conversation, not to a speaker.
- **Home is unchanged on purpose**: there is no conversation `StatCard` and no conversation link card on `/`. The "keep the destination list in sync with the sidebar" rule in the Home section is deliberately broken until the user asks for it.

### 8. Authentication
- **Server logic lives in** `src/server/services/auth.service.ts`; route handlers in `src/app/api/auth/*` only parse input, call the service, and return `{ success, message, data }`. Never call another route handler over HTTP.
- **Validation**: Use the Zod schemas in `src/lib/validations/auth.ts`. Errors flow through `ApiError` and `handleApiError` (`src/lib/api-error.ts`), which maps `ZodError` to `400` and `ApiError` to its status.
- **Tokens**: HS512 JWTs. Access token lasts 30 minutes in the `accessToken` httpOnly cookie; refresh token lasts 7 days in `refreshToken`. Store only the SHA-256 hash of the refresh token. Refresh tokens are single-use with a 30-second grace period, rotate on use, and reuse past the grace period deletes all sessions for that user.
- **Read-only role resolution**: `resolveSessionRole()` verifies the access token (falling back to *validating*, never rotating, the refresh token) and returns the role or `null`; `canViewUnpublishedContent()` maps that to `role === "admin"`. Because neither writes a cookie, a Server Component may call them — unlike `resolveSessionUser()`, whose refresh logic reissues tokens. Any failure, expired token, or non-admin role resolves to `false`, so the published-only rule fails closed and a hand-typed `?status=draft` can never widen a public reader's view.
- **Cookies**: Build options in `src/lib/auth/tokens.ts` — `httpOnly`, `path: "/"`, `sameSite=lax` in development and `secure` + `sameSite=none` in production. Use `cookies()` from `next/headers` (async in Next 16); clear both cookies on logout.
- **Passwords**: Always hash with `hashPassword` (bcryptjs, `HASH_SALT_ROUNDS`, default 10). Never store or log plaintext. Google-created users have no password and `isComplete: false` until they complete the profile.
- **Registration**: `/api/auth/register` creates a `public` user and does not sign them in. Duplicate emails return `409`. `/api/auth/register-admin` creates an `admin` user only when `adminSecretKey` matches `ADMIN_REGISTER_KEY`; otherwise `403`.
- **Google login**: The client uses the implicit flow (`@react-oauth/google`, `useGoogleLogin`). The API exchanges the access token at `https://www.googleapis.com/oauth2/v3/userinfo`. `GoogleAuthProvider` renders only when `NEXT_PUBLIC_GOOGLE_CLIENT_ID` is set, and the button stays disabled with a notice otherwise. Do not test Google login with real credentials in automation.
- **Client state**: `AuthProvider` (`src/features/auth/AuthProvider.tsx`) owns `user`, `isAuthLoading`, and `activeModal`. Fetch `/api/auth/profile` on mount and treat `401` as signed out. Use `setAuthenticatedUser` after login/complete-profile, `updateAuthenticatedUser` after a profile edit (it only replaces the cached user and never reopens the complete-profile modal), and `logout` for sign-out.
- **Account updates**: `PATCH /api/auth/update-profile` changes **only** the name through `updateProfileSchema` and returns the fresh user. `PATCH /api/auth/update-password` verifies `currentPassword` with `verifyPassword`, returns `401` on a mismatch, `400` when the account has no password (Google sign-in only), hashes the new password, and calls `startSession()` so the current device stays signed in and older refresh tokens are dropped. Both require a session via `requireSessionUser()` and await `connection()` before the `try` block.
- **Modals**: Login, register, and complete-profile are modal flows (`src/features/auth/AuthModals.tsx`), mounted from `Navbar`. **Update profile** and **Update password** open from `UserMenu`, which owns that local modal state and renders `UpdateProfileForm` / `UpdatePasswordForm` conditionally so each open starts with a clean form. Keep the user menu in `src/components/shared/UserMenu.tsx`.
- **Hidden admin page**: `/admin-register` must stay unlinked from the sidebar and keep `robots: { index: false, follow: false }`.
- **Environment**: `JWT_ACCESS_TOKEN_SECRET`, `JWT_REFRESH_TOKEN_SECRET`, `HASH_SALT_ROUNDS`, `ADMIN_REGISTER_KEY`, and `NEXT_PUBLIC_GOOGLE_CLIENT_ID`. `.env` stays gitignored; update `.env.example` with placeholders only.

### 9. Practice Feature (IPA & Speech)
- **Client islands**: `src/features/practice/PracticeWorkspace.tsx` owns the editable text and renders `useSpeechPractice.ts`, `SpeechPracticeControls.tsx`, and `IpaTranscriptionCard.tsx`. `src/features/presentation/PresentationPracticeWorkspace.tsx` reuses that advanced set with the saved `title` and `text`. Both workspaces put `CopyTextButton` (`src/features/practice/CopyTextButton.tsx`) in the top-right of the text card header — `flex flex-col gap-3 sm:flex-row sm:items-start sm:justify-between`, the same header split the IPA card already uses — as a `secondary` button that copies the current text through `navigator.clipboard`, so it is `disabled` while the text is blank; the shared `Previous`/`Next` nav row uses the same `secondary` recipe. `src/features/sentence/SentencePracticePanel.tsx` and `src/features/vocabulary/VocabularyPracticePanel.tsx` use the listen-only set (`useIpaTranscription`, `InlineIpa`, `useListenSpeech`, `PlayTextButton`, `ListenControls`), where IPA appears automatically and the learner chooses accent, voice, and speed. `src/features/conversation/ConversationPracticeWorkspace.tsx` uses neither set: it drives `useConversationPractice`, the two-voice chain described in the Conversation section, and must not be collapsed into the single-voice hook. The Practice, Presentation, Sentences, Vocabulary, and Conversation pages remain Server Components.
- **Text changes**: Cancel playback and reset the IPA state through `practice.handleTextEdited()` when the editable text changes. Saved presentation and sentence text never changes in the browser, so those callers do not need that hook.
- **IPA**: Import `phonemize` dynamically inside the transcription effect so its pronunciation data stays out of the initial bundle. Pass the selected dialect (`en-GB` / `en-US`), debounce text changes, and handle loading and failure states. The advanced card produces both a full transcription and sentence pairs so the "Sentence by sentence" / "Full translation" view dropdown can switch without recomputing; the listen-only `useIpaTranscription` hook skips sentence pairs because every inline item is transcribed on its own.
- **Sentence splitting**: Use `Intl.Segmenter` with `granularity: "sentence"` and treat newlines as hard boundaries. Merge segments that end in a known abbreviation (`Mr.`, `Dr.`, `e.g.`, `Jan.`), a single capital initial, or a list number so they are not shown as separate cards. `useSpeechPractice(text, title)` splits the title and the body **separately** and marks the title pairs with `isTitle`, so a title ending in a period can never merge into the first body sentence; the IPA card shows an info `Badge` labelled "Title" above those pairs, renders them at `font-semibold`, labels their Listen button "Listen to the title", and numbers body sentences from 1 by subtracting the title pair count.
- **Speech**: Use `window.speechSynthesis` and `SpeechSynthesisUtterance`. Set `utterance.rate` from the Speed dropdown, cancel playback when the text, accent, voice, or speed changes, on reset, and on unmount. Guard callbacks with the active utterance ref so a cancelled utterance cannot overwrite newer playback state. One `speakText(value, sentenceIndex)` path serves both the whole-text **Start/Pause** button and the per-sentence **Listen** buttons in `IpaTranscriptionCard`, so both inherit the same accent, speed, and voice fallback; `playingSentenceIndex` tracks which card is playing (`null` for the full text). Playback is **one flip button** (`handleStartPause`): `idle` or `paused` shows **Start** + `FiPlay` and calls `resume()` when an utterance is already paused, so pausing never rewinds; `speaking` shows **Pause** + `FiPause` and calls `pause()`. There is no separate Pause control — do not add one back. **Reset** (`secondary`, disabled while `idle`) cancels to the initial state so the next Start speaks from the beginning, and it keeps the repeat setting. **Repeat** is the icon-only `Button` after the flip button: `<RiLoopRightLine />` (react-icons `ri`) with no visible text, `title` and `aria-label` "Repeat", `aria-pressed={repeat}`, `h-9 w-full border-slate-400 sm:w-auto`, `variant={repeat ? "secondary" : "white"}` so it reads white when off and slate-700 when on — it toggles like a checkmark, it is not a checkbox input. The `border-slate-400` in `className` deliberately overrides the `white` variant's `border-slate-200` so the off state is a clearly visible control (Tailwind emits the darker shade later in the sheet, so it wins); `secondary` sets no border width, so the class is inert when on and must not be dropped. When on, `utterance.onend` re-enters `speakText` synchronously for the whole text only (`sentenceIndex === null`), so a sentence card stays one-shot. Read the toggle through `repeatRef` because a running utterance keeps the callbacks from the render that started it, and restart from `onend` (never a timer) so the existing active-utterance guard stays authoritative: Reset, an accent/voice/speed change, or a newer utterance nulls the ref first and the loop cannot fire. Do not add a second speech engine to the advanced workspace.
- **Voice availability**: Voices are supplied by the OS/browser. Every listen surface has a **Voice** dropdown immediately after **Accent**, listing only that accent's voices through `buildVoiceOptions()` with `Automatic (best match)` first. Automatic prefers an exact `en-GB`/`en-US` voice; if none exists, leave the voice unset and show the fallback notice instead of silently using the wrong accent. A hand-picked voice is session-only React state, is cleared when the accent changes (a voice belonged to the accent it was listed under), and stops playback with a notice naming the change so the learner restarts deliberately.
- **Responsive layout**: Keep the workspace on the shared card styling (`rounded-xl border-slate-200`). The advanced controls row is `grid-cols-1 sm:grid-cols-2 xl:grid-cols-4` — Accent, Voice, Speed, Show IPA; `ListenControls` is `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` — Accent, Voice, Speed — or a single column when the caller passes `stacked`. Action buttons are full width below `sm` and auto width above. Verify no horizontal overflow at 390 px, 768 px, and 1440 px.
- **Browser persistence**: The practice text is saved to `localStorage` under `spoken-english-practice:text` on every edit and read through `useSyncExternalStore` so hydration stays consistent; emptying the textarea removes the entry. IPA and audio remain session-only. Do not add database writes or audio uploads until a requirement defines them.
